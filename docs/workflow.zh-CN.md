# 终端优先的 Android 逆向工作流

本仓库不重写 JADX、IDA、Frida，也不要求安装一个大型 MCP。先把确定性工作交给成熟工具，保留本地文件，Agent 再按问题阅读、检索和复算。

## 已经能做什么

- `mrat fingerprint PATH`：流式计算文件 SHA-256 和大小，不上传文件。
- `mrat search-exports DIRECTORY QUERY --limit 30`：检索 IDA/JADX 的本地文本导出，返回文件、行号与截断状态。不是语义 xref。
- `mrat generate-java-hook ...`：针对精确重载生成 Frida 脚本；只生成，不连接手机。
- `mrat summarize-events PATH`：检查 JSONL 基本事件信封并统计。通过不代表证据真实或采集完整。

## Java 静态

先登记 APK，再按 Manifest、字段、字符串或 API 定位类。先读骨架再读方法；用语义引用工具追调用者，必要时以 Smali/DEX invoke 复核。大型多 DEX 按定义与引用范围缩小输入。反射、动态加载和接口实施类不能凭静态关系确认。

语义引用由外部分析工具完成；既有工作方式使用过 JADX CLI＋xref JAR。本仓库不重新实现或分发这些工具，也不将尚在调研的外部项目列为依赖。

## Native 静态

IDA/Hex-Rays 批量导出伪码、汇编、函数元数据与索引。Agent 本地检索后读取相关函数，使用 JNI 注册、调用关系、结构体访问、vtable 和 relocation 继续定位。

伪码失败先读汇编；函数边界错误则针对性修复后重导。OLLVM、字符串加密、间接跳转只处理妨碍当前问题的部分。结构恢复和 Unicorn 调试是独立能力，不能用“反编译成功”替代。

## 动态与流量

按真实场景定义实验，外部 Frida Runner 负责 spawn/attach、加载、resume、message、持续采集与 cleanup。MITM 保存实际请求，进程内 Hook 补充明文与加密边界。页面、线程、调用序号、缓冲区与请求通过同轮字节和哈希交叉对应。


## Trace 与离线恢复

系统行为追踪、函数边界观测、自定义 VM 指令轨迹必须分开标注。ftrace/uprobe 不是 HTTPS 解密器；对象级调用日志不是完整指令轨迹。对目标 VM 可逐步恢复指令含义、建立离线寄存器/内存模型、跨输入比较，再把已验证部分化简为普通代码。

独立复算不得使用最终输出反推的中间结果作为输入。算法相似不等于标准算法；HTTP 200 不证明签名校验通过。

## 开源边界

只抽取通用代码与合成测试。公司材料、业务样本、设备画像、请求凭据和第三方私有代码不属于本仓库。外部项目与工具应记录来源和许可，复用时保留通知。

REA/Hooker 可作为可选实现参考或后端，不是必须依赖。是否接入应由同任务耗时、输出规模和实际可用性决定。
